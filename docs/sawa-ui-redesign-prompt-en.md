# Sawa UI Redesign — Implementation Prompt

## Role

You are a senior frontend engineer and product designer. You are working inside the existing `Spetser-0/sawa` repository. Redesign the user interface using the supplied ORYZO-inspired editorial design system. Do not create a mockup only: modify the real application, preserve all existing product behavior, and leave the project buildable.

## Main objective

Replace the current neon green / purple / glassmorphism visual language with a restrained warm editorial interface that feels intentionally designed by a human product team rather than generated by AI.

The redesign must be applied to the real React frontend under:

```text
front_end/src/
```

The application uses React, Vite, React Router, `lucide-react`, and plain CSS. Do not migrate frameworks, replace the router, or rewrite working API/authentication logic.

## Design direction

### 1. Color philosophy

- Use `#100904` as the page canvas and deepest surface.
- Use `#ffedd7` for primary text, headings, navigation, and important icon strokes.
- Use `#382416` for elevated surfaces and the rare filled primary action.
- Use `#40372e` for subtle borders and dashed dividers.
- Use `#6c5f51` for secondary text and muted structure.
- Use `#dc5000` sparingly for short editorial accents, links, credits, errors, and warnings.
- Never use pure white for normal text.
- Never use neon green, bright purple, blue, pink, or rainbow gradients.

### 2. Layout philosophy

- Prefer full-width editorial sections and intentional negative space.
- Avoid dense dashboard grids and repeated rounded cards.
- Keep content left-aligned within its logical writing direction.
- Use a clear visual hierarchy: small uppercase label, strong heading, quiet explanatory copy.
- Use one statement per section instead of multiple competing panels.
- Keep the existing Arabic RTL and English LTR behavior working.

### 3. Surface and depth philosophy

- Do not use drop shadows for normal cards, buttons, navigation, or sections.
- Do not use glassmorphism or heavy backdrop blur as the primary visual treatment.
- Create depth with the contrast between walnut canvas and bark surface.
- Use only 1px borders and occasional dashed 1px dividers.
- Cards may use a 12px radius; do not use many unrelated radius values.

### 4. Typography voice

- Navigation, labels, headings, buttons, badges, and metadata should be uppercase where the language permits.
- Use weight 500 for labels and headings.
- Use weight 400 for conversational descriptive copy.
- Keep letter spacing normal; do not use excessive tracking.
- Keep display headings tight with approximately `0.9` line-height.
- Do not make every element bold.

## Implementation steps

### Step 0 — Inspect before editing

1. Inspect `front_end/src/App.jsx`, `front_end/src/index.css`, `front_end/src/components/`, and `front_end/src/pages/`.
2. List all routes and identify shared components.
3. Search for hard-coded legacy colors and effects:

```bash
rg -n "#34D399|#818CF8|#60A5FA|#F472B6|#C084FC|#F59E0B|#F87171|#FCD34D|gradient|boxShadow|backdrop-filter" front_end/src
```

4. Do not remove functional states, API calls, auth flows, upload flows, media controls, analytics, or translations.

### Step 1 — Install the token layer

1. Import the runtime variable file from `front_end/src/index.css`.
2. Make sure `variables.css` contains valid browser CSS and corrects the border token to `#40372e`.
3. Keep `theme.css` and `tokens.json` as readable source references.
4. Add compatibility aliases only when needed to avoid breaking existing components, for example:

```css
--bg: var(--color-walnut-shadow);
--bg-card: #1b100a;
--bg-elevated: var(--color-bark-brown);
--border: var(--color-cork-border);
--text: var(--color-warm-cream);
--text-muted: var(--color-driftwood);
```

5. Prefer semantic names over direct hex values in application code.

### Step 2 — Rebuild global CSS

Update `front_end/src/index.css`:

- Set the body background to walnut shadow.
- Set body text to warm cream.
- Use the design font stack.
- Make focus rings warm cream or ember and keep them clearly visible.
- Restyle buttons:
  - Filled button: bark brown background, warm cream text, 36px radius.
  - Outline button: transparent background, 1px cream/cork border, 22.5px radius.
  - Text link: no container, underline on hover/active.
- Restyle cards with bark/walnut surfaces, 12px radius, 1px cork border, and no shadow.
- Restyle inputs using an underline or restrained cork border; avoid heavy boxed controls.
- Restyle alerts, badges, skeletons, empty states, uploader states, and modals to use the same token vocabulary.
- Keep responsive breakpoints and reduced-motion support.

### Step 3 — Redesign shared navigation

Update `front_end/src/components/Navbar.jsx` and its CSS:

- Keep the existing routes and auth behavior.
- Use a quiet transparent/sticky navigation over the walnut canvas.
- Make the Sawa wordmark typographic, warm cream, and visually confident.
- Use a maximum of four primary navigation items when possible.
- Replace gradient logo text and neon beta pills.
- Use underline or dashed active indicators instead of filled colored tabs.
- Keep the mobile menu fully functional and keyboard accessible.
- Keep the language toggle and account menu functional.

### Step 4 — Redesign the landing page

Update `front_end/src/pages/Home.jsx`:

- Remove the animated neon mesh, rainbow gradients, excessive glow, and decorative 3D tilt effects that make the page feel AI-generated.
- Keep the real copy, links, translation keys, and product explanation.
- Use a calm editorial hero with generous negative space.
- Use a large typographic Sawa wordmark/headline.
- Use one primary filled CTA maximum per section.
- Use outlined or text links for secondary actions.
- Convert feature cards into restrained editorial blocks with cork dividers.
- Keep product mockups, statistics, comparison, pricing, and CTA content, but flatten their surfaces and reduce visual noise.
- Use dashed hairline separators between major sections.
- Remove unnecessary shadows and blur.
- On mobile, stack sections naturally and preserve readable Arabic line lengths.

Apply the same system to:

Requirements:

- Preserve every API call and user action.
- Preserve loading, success, error, empty, and disabled states.
- Replace direct neon colors with design tokens.
- Use ember only as a restrained status/accent color, not as a primary button fill.
- Keep charts readable; use cream, driftwood, bark, cork, and ember only.
- Keep destructive actions visibly distinct but not neon.
- Keep media controls high-contrast and usable.
- Keep forms usable in both RTL and LTR.

### Step 6 — Accessibility and responsive behavior

Verify:

- Text contrast is readable against walnut and bark surfaces.
- Every icon-only button has an accessible label.
- Keyboard focus is visible.
- Touch targets are at least approximately 40px.
- No horizontal overflow at 320px width.
- Dashboard, recorder, uploader, watch page, settings, and pricing remain usable at 375px, 768px, and 1280px widths.
- Reduced-motion users do not receive distracting animation.
